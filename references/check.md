## 리포트 읽어 주기 (채팅)
```
점검했어요 · ○ (n) · △ (n) · ✕ (n)
고칠 것
- (✕ 이름): (고치는 법 한 줄)
- (△ 이름): (고치는 법 한 줄)
```
✕ 가 없으면: 「검색엔진과 AI 가 읽는 데 막힌 곳은 없어요.」 + 다음(「색인 등록 도와줘」).

## 고칠 때 (「고쳐 줘」 · 직접 지은 사이트)
| 걸린 것 | 고치는 곳 |
|---|---|
| 제목 · 설명 · H1 · 문구 | site-plan.json → `build.mjs --update` (src/site.json 이 같이 바뀜) |
| 300자 안 | 그 페이지가 답할 사실을 묻고 sections 에 더하기. 문의 페이지처럼 원래 짧은 곳은 그대로 둬도 된다고 말하기 |
| 사이트맵 · robots · 대표 주소 | 손대지 않았다면 주소(url)가 틀린 경우가 많다 → site-plan.json url 확인 |
| 파비콘 · 공유 카드 | `site/public/` 의 그림을 지우고 `npm run icons` |
| AI 봇 막힘 | 코드 문제가 아니다. Cloudflare · 호스팅의 봇 차단 설정 (사람이) |
고친 뒤: `npm run build` → 다시 올리기(사람) → 「내 사이트 점검해 줘」.

## 빌더 사이트 (`--builder`)
- 고치는 법이 「빌더 관리 화면에서 …」 문구로 나온다. 화면 조작은 사람이.
- 빌더에서 못 바꾸는 것(구조화 데이터 · 404 · robots 일부)은 「넘어가도 돼요」라고 말한다. 대신 제목 · 설명 · H1 · 글자 · 봇 차단은 꼭.
- 넣을 문구는 컨셉 리포트의 사이트 칸(칸마다 복사)을 쓰라고 안내한다.

## site-check.json
```
{ date, url, builder, local, preview, count: { ok, warn, bad, later }, ready, results: [{ id, name, level, detail, fix, how, pages? }], pages: [{ url, title, titleLen, description, descLen, h1, canonical, textLen, types }] }
```
`ready` = ✕ 없음 · 진짜 주소. geo-index 는 ready 가 false 면 등록 전에 「먼저 사이트 리포트의 ✕ 를 고쳐요」라고 말한다.
